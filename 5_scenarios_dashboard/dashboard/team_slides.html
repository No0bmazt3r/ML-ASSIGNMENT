# some files use M/D/Y and some D/M/Y, so we try both
def date_format(first_date: str, start: datetime) -> str:
    for fmt in ("%m/%d/%Y", "%d/%m/%Y"):
        try:
            if datetime.strptime(first_date, fmt) == start:
                return fmt
        except ValueError:
            pass
    raise ValueError(f"first date {first_date!r} matches neither format")

# week 4 has the main meter file spelt wrong (Aggregtae.csv)
FILE_ALIASES = {"Aggregate": ["Aggregate.csv", "Aggregtae.csv"]}

Point 1 is the date fix. Instead of guessing the format, I check which format turns the first row into the folder's known start date.

Point 3: when averaging to one minute I also keep the spread inside the minute. Point 4 removes the outage, because zero power during a blackout would teach the model something false.

Part 2 of 5

Feature engineering and baselines

I turned each minute of main-meter readings into 98 numbers a model can learn from.

  • Harmonic ratios. Each harmonic compared with the fundamental, per phase. Inverter A/C compressors have a distinct pattern.
  • Gap-safe lags. Past power values that never reach across a missing day or the outage.
  • Calendar features. Hour as sine and cosine, weekday, weekend and office hours.
  • Redundancy check and baselines. I flagged near-duplicate features and set up the time-of-day baseline that every model has to beat.

The important line is the segment trick in point 2. The data has gaps, like the outage and missing days. A normal shift would give the first minute after a gap a value from hours earlier.

So I give every unbroken stretch its own number and shift only inside it. The assert in point 5 checks it on every run.

Part 3 of 5

Models, freeze and test

I picked the model fairly, locked it in, and tested it once on a week nobody had touched.

  • Five models. Time-of-day average, Ridge, Random Forest, XGBoost and LightGBM, each with a small grid.
  • Time-ordered cross-validation. 4 folds in time order, with a 60-minute gap so the past never sees the future.
  • A rule written first. A tree model only wins if it beats Ridge by at least 5%.
  • Freeze, then test. I saved freeze.json before week 6 was loaded, then ran one test with bootstrap confidence intervals.

Point 2 is the key decision. Our features come in correlated families. If you shuffle one harmonic alone, the others still carry the information, so it looks unimportant. Shuffling the whole group fixes that.

For clustering, I scale every day to its own peak, so the clusters are about the shape of the day. The silhouette score chose two clusters.
